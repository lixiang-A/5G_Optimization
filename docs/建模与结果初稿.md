# 建模与结果初稿

本文档用于论文写作阶段的中文初稿整理，当前仅写入已经被仓库文件、脚本和结果输出共同支撑的内容，重点覆盖前三问的建模部分，以及第 1、2、3 问当前可核验的结果分析。原始约束来自 `背景信息/第三次训练赛.docx`、`背景信息/附录.pdf` 与 `背景信息/5G环境开发设计文档 (1).md`；数值结果来自仓库现有脚本和输出文件，不额外引入未经验证的设定。

## 一、问题重述与研究目标

赛题研究的是 5G 异构切片环境下的无线资源管理问题。系统需要在 URLLC、eMBB、mMTC 三类业务之间划分资源块，并在多基站场景下进一步联合控制发射功率，以提升整体用户服务质量。根据题面，系统每 `100 ms` 进行一次资源重配置，而单个资源块在时域上的跨度为 `1 ms`、在频域上的跨度为 `360 kHz`。因此，本文将前三问统一重述为一个双时间尺度下的切片资源优化问题：在慢时间尺度上完成切片资源预算与功率决策，在快时间尺度上完成队列服务、任务传输和资源释放。

前三问的结构可统一表述为：

- 问题 1：单微基站、单时刻、静态任务集下的切片资源块分配问题。
- 问题 2：单微基站、`1000 ms` 时域内 `10` 次资源重配置下的动态切片分配问题。
- 问题 3：多微基站频率复用和同频干扰存在时的切片资源分配与功率联合控制问题。

论文的核心目标不是简单“把资源块分出去”，而是在题面给定的 SLA、任务流、信道演化和干扰结构约束下，最大化系统整体用户服务质量。

## 二、系统模型与统一建模基础

### 2.1 基本资源与时间尺度

依据 `背景信息/第三次训练赛.docx` 与 `背景信息/附录.pdf`，每个微基站拥有 `50` 个 RB。系统每 `100 ms` 重新决策一次资源配置方案，但任务在 `1 ms` 粒度上完成排队、发送、释放与切换。因此本文采用双时间尺度建模：

- 决策层时间尺度：`100 ms`
- 执行层时间尺度：`1 ms`

这一定义既符合题面“每隔一段时间重新分配资源”的设定，也保证 URLLC 的毫秒级时延约束能够在模型中被显式刻画。

### 2.2 三类切片参数

依据 `背景信息/附录.pdf` 表 1，三类切片的核心参数如下：

- URLLC：每个用户占用 `10` 个 RB，速率 SLA 为 `10 Mbps`，时延 SLA 为 `5 ms`，任务数据量范围为 `0.01` 到 `0.012 Mbit`，惩罚系数为 `5`，效用折扣系数为 `0.95`。
- eMBB：每个用户占用 `5` 个 RB，速率 SLA 为 `50 Mbps`，时延 SLA 为 `100 ms`，任务数据量范围为 `0.1` 到 `0.12 Mbit`，惩罚系数为 `3`。
- mMTC：每个用户占用 `2` 个 RB，速率 SLA 为 `1 Mbps`，时延 SLA 为 `500 ms`，任务数据量范围为 `0.012` 到 `0.014 Mbit`，惩罚系数为 `1`。

因此，在任一决策时刻，若三类切片的资源块数分别记为 `x_u, x_e, x_m`，则需要满足：

`x_u + x_e + x_m = 50`

同时满足颗粒度约束：

- `x_u` 为 `10` 的整数倍
- `x_e` 为 `5` 的整数倍
- `x_m` 为 `2` 的整数倍

### 2.3 传输速率与服务质量

附录给出了信号传输模型、信干噪比模型和香农公式，仓库脚本 `channel_data等2个文件/solve_q1.py` 与 `q2_mpc.py` 对这些公式做了直接实现。对任一用户任务，传输速率由路径损耗、小尺度瑞丽衰落、发射功率、噪声功率与 RB 数共同决定。第 1、2 问采用固定发射功率 `30 dBm`，这是题面补充说明给出的默认设定；第 3 问中每个基站每类切片的发射功率允许在 `10` 到 `30 dBm` 范围内调节。

服务质量函数同样遵循附录设定：

- URLLC 重点考察超低时延，若任务在 `5 ms` 内完成，则效用随时延增加按 `0.95^d` 衰减；若超时则给予惩罚。
- eMBB 在满足 `100 ms` 时延约束的前提下，按实际传输速率相对 `50 Mbps` 速率 SLA 的达成比例计分；超时则惩罚。
- mMTC 更强调接入成功性，在时延约束内按成功接入比例给出质量评估；超时则惩罚。

由此可以将三类切片的平均服务质量加权汇总为系统目标值。

## 三、分题建模写作

### 3.1 问题 1：静态单基站切片分配模型

问题 1 对应的数据文件为 `channel_data等2个文件/channel_data.xlsx`，求解脚本为 `channel_data等2个文件/solve_q1.py`。该问题中只有一个微基站、一个决策时刻，且任务集合已经给定，因此本质上是一个小规模离散枚举问题，而不是需要强化学习的动态控制问题。

建模时，可将决策变量定义为三类切片的资源块划分 `(x_u, x_e, x_m)`。给定一组划分后，各类任务在其对应切片内按照固定 RB 占用量并行传输；若同类用户数超过当前切片的可服务并行数，则按题面与附录规定的顺序优先服务编号靠前的用户。由于该问题规模极小，完全可以对全部满足颗粒度约束的分配方案进行穷举，并逐一计算三类切片的服务质量均值，从而得到全局最优解。

这种写法的优点在于逻辑完全闭合：数据来自题目附件，速率计算来自附录，服务质量定义来自附录，优化方式则由问题规模直接决定，不需要额外引入未经验证的学习机制。

### 3.2 问题 2：动态单基站滚动优化模型

问题 2 对应的数据文件为 `channel_data等2个文件(1)/channel_data.xlsx`，求解脚本为 `q2_mpc.py`。与问题 1 相比，该问题的难点不再是单次静态分配，而是需要在 `1000 ms` 范围内面对随机任务到达、队列积压和信道变化，在 `10` 个决策窗口内连续调整切片资源。

在 `q2_mpc.py` 中，系统状态主要由当前时刻、三类队列中的未完成任务、未来窗口内任务到达情况以及对应信道速率构成；每次动作仍然是三类切片在 `50` 个 RB 内的整数划分方案。脚本使用滚动预测的 DP/MPC 思想：对每个候选动作，向前看若干个决策窗口，计算其在未来演化中的目标值，再选择当前时刻的最优动作。窗口内部则按照 `1 ms` 粒度推进任务服务过程，并在窗口末对仍未按 SLA 完成的任务施加终端惩罚。

从论文写作角度，这一部分最适合表述为“有限时域滚动优化基线”。它一方面比简单贪心策略更能体现对未来队列压力的考虑，另一方面又为后续强化学习方法提供了一个可对照、可解释的强基线。

### 3.3 问题 3：多基站干扰耦合下的分层联合优化模型

问题 3 使用 `BS2等5个文件/BS1.xlsx`、`BS2等5个文件/BS2.xlsx`、`BS2等5个文件/BS3.xlsx` 和 `BS2等5个文件/taskflow.xlsx` 作为输入，核心代码为 `q3_hierarchical_rl.py` 与 `q3_sb3.py`。题面要求在多个微基站同时复用频谱时，同时给出切片 RB 分配方案与功率控制方案，因此系统需要同时考虑队列需求、链路质量和跨站干扰。

当前仓库实现采用双层分解思路：

- 切片层：先在基站层面对三类切片的 RB 预算进行离散决策。
- 功率层：在切片预算给定的基础上，对每个基站各切片的发射功率进行连续控制。

这种写法与参考文献 `背景信息/Reinforcement-Learning-Based_Network_Slicing_and_Resource_Allocation_for_Multi-Access_Edge_Computing_Networks.pdf` 的“两层切片与资源分配”思想保持一致，但没有照搬其 MEC 计算资源分配背景，而是根据本题实际结构将第二层替换为功率控制与干扰协调，因此在论文中是合理且可自洽的。

需要明确指出的是，当前 `q3_hierarchical_rl.py` 与 `q3_sb3.py` 中还采用了一个显式建模假设：任务到达后由最近的微基站提供服务，接入模式优化不在当前前三问范围内。这个假设应在论文中单独声明，而不能写成题面直接给定的条件。

## 四、结果写作与分析

### 4.1 问题 1 的可核验结果

问题 1 的结果来自命令 `python3 channel_data等2个文件/solve_q1.py` 的直接运行输出，使用的数据文件为 `channel_data等2个文件/channel_data.xlsx`。在默认等权重设置下，三组分配方案并列最优：

- `(30, 10, 10)`
- `(20, 20, 10)`
- `(20, 10, 20)`

三组方案对应的三类切片服务质量分别为：

- `Q_u = 0.993482`
- `Q_e = 0.948832`
- `Q_m = 1.000000`
- 综合目标值 `U = 0.980771`

这一结果说明，在当前单时刻数据下，系统容量足以同时满足三类业务的基本要求，因此问题 1 的最优解并不是唯一的。更准确地说，只要 URLLC 至少获得 `20` 个 RB 或者通过更高并行度使其低时延需求完全满足，同时 eMBB 与 mMTC 维持可行服务能力，就会出现若干等效最优方案。这一现象在论文中可以解释为：静态小规模场景下的资源约束尚未充分紧张，因此最优解呈现“多解并列”特征。

### 4.2 问题 2 的结果与分析

问题 2 的结果文件分别为：

- `outputs/q2_mpc/lookahead1.json`
- `outputs/q2_mpc/lookahead2.json`
- `outputs/q2_mpc/lookahead3.json`

对应目标值为：

- `lookahead = 1` 时，`objective = 0.8492915076842188`
- `lookahead = 2` 时，`objective = 0.8986439771627552`
- `lookahead = 3` 时，`objective = 0.8877485078261866`

其中 `lookahead = 2` 的细化结果最值得写入正文。根据 `outputs/q2_mpc/lookahead2.json`，在该设置下：

- URLLC 完成任务数为 `216`，丢弃 `1` 个，平均时延为 `2.4960 ms`
- eMBB 完成任务数为 `1931`，丢弃 `25` 个，平均时延为 `16.7218 ms`
- mMTC 完成任务数为 `7010`，丢弃 `0` 个，平均时延为 `15.7955 ms`
- eMBB 平均服务速率为 `44.9974 Mbps`

再结合运行时间文件：

- `outputs/q2_mpc/lookahead2_time.txt` 显示总耗时约 `36.08 s`
- `outputs/q2_mpc/lookahead3_time.txt` 显示总耗时约 `645.62 s`

因此，问题 2 可以形成一个比较清晰的论文结论：从 `lookahead = 1` 提升到 `lookahead = 2` 时，系统目标值显著上升，说明适度前瞻确实能够改善动态资源配置效果；但进一步增加到 `lookahead = 3` 后，目标值没有继续提升，计算代价却急剧增大，表明更深层的滚动预测在当前问题规模和数据下已经出现边际收益递减。因此，`lookahead = 2` 是当前模型下目标值与计算复杂度之间的最佳折中。

### 4.3 问题 3 的结果与分析

问题 3 的当前可核验结果主要来自以下文件：

- `outputs/q3_rl/short_run_metrics.json`
- `outputs/q3_sb3/q3_combined_eval_fresh_10k.json`
- `outputs/q3_sb3/q3_combined_eval_seed17_10k.json`
- `outputs/q3_sb3/q3_combined_eval_seed27_10k.json`

首先，轻量级 numpy 分层基线在 `outputs/q3_rl/short_run_metrics.json` 中给出的最佳评估目标值为 `0.4552520100347934`。在此基础上，`q3_sb3.py` 实现的分层 PPO 在三个随机种子下的联合评估结果为：

- `seed = 7` 时，`objective = 0.49188382075400083`
- `seed = 17` 时，`objective = 0.4994806473699616`
- `seed = 27` 时，`objective = 0.4965230144859628`

三组结果的目标值均值为 `0.4959624942033084`，标准差为 `0.0031266148786072943`。这说明当前分层 PPO 相较于轻量级基线存在稳定提升，而且不同随机种子下的波动较小，已经具备作为论文主结果的基本稳定性。

其中，`seed = 17` 可作为正文主展示结果。根据 `outputs/q3_sb3/q3_combined_eval_seed17_10k.json`：

- 综合目标值为 `0.4994806473699616`
- URLLC 完成 `559` 个任务，丢弃 `0` 个，平均时延 `1.2795 ms`
- eMBB 完成 `5406` 个任务，丢弃 `587` 个，平均时延 `99.9393 ms`
- mMTC 完成 `10527` 个任务，丢弃 `10556` 个，平均时延 `398.5841 ms`
- eMBB 平均服务速率为 `112.2346 Mbps`
- 平均发射功率为 `0.1032 W`
- 平均干扰比为 `0.3555`

从结果解读上看，当前模型已经比较稳定地保障了 URLLC 的关键指标，三组复现实验均实现了 `0` 个 URLLC 丢弃任务，且平均时延明显低于 `5 ms` 的硬约束；eMBB 的平均时延接近 `100 ms` 边界，但平均服务速率显著高于 `50 Mbps` 的 SLA，说明模型在高吞吐与时延约束之间处于紧平衡状态；mMTC 仍是当前框架中最难服务的切片，这与其大规模接入、资源竞争激烈以及多基站干扰耦合场景下的弱势特征一致。

因此，问题 3 现阶段更合适的论文表述不是“所有业务都已充分优化”，而是“分层联合控制方法已经在核心高优先级业务 URLLC 上展现出稳定保障能力，并在综合目标值上稳定优于轻量级基线，但 eMBB 的时延裕度和 mMTC 的服务能力仍然是后续可继续优化的方向”。这种表述既符合当前结果，也更加严谨。
